은재와 한 실험: batch 크기와 8비트 양자화
============================================

이번에 물어본 것
1. batch를 4에서 8로 늘리면 학습이 빨라질까?
2. 이미 학습한 모델의 실행 메모리를 줄여도 그릇을 옮길까?

공통 출발점
- 기본 모델: openvla/openvla-7b
- LoRA rank 8, 총 5 epoch를 학습한 기존 체크포인트
- 공개 LIBERO 데이터에서 선택·전처리한 실험용 분할:
  학습 전체 시범 40개(4,025개 장면), 검증 전체 시범 5개(462개 장면).
  시범 40개는 사진 40장이 아니라 처음부터 끝까지 이어지는 시범 40개다.

1. batch 실험: 같은 문제를 몇 개씩 묶어서 공부할까?
- 같은 5 epoch 모델에서 출발해 각각 준비용 16개, 측정용 128개 장면만 학습했다.
- batch 4: 12.54초, 최대 GPU 메모리 14.92 GiB.
- batch 8: 11.10초, 최대 GPU 메모리 15.69 GiB.
- 이번 짧은 측정에서는 batch 8의 시간이 약 11.5% 적었다.
- 대신 메모리는 약 0.76 GiB 더 필요했다.
- 128개 장면에서 가중치를 고치는 횟수는 batch 4가 32번, batch 8이 16번이다.
- 따라서 속도만 확인했다. batch 8로 5 epoch 전체를 학습한 성능은 아직 모른다.
- 시험하면서 바뀐 가중치는 원래 모델에 저장하지 않았다.

2. 양자화 실험: 같은 모델의 숫자를 적은 비트로 표현하면?
- batch 시험 결과를 사용하지 않고, 원래 5 epoch LoRA를 다시 불러왔다.
- 언어모델의 선형층 224개를 8비트로 불러왔다.
- 사진 처리 부분·연결층·마지막 출력층은 BF16, LoRA는 FP32로 유지했다.
- 7B라는 모델의 파라미터 개수를 줄인 것은 아니다.
- 기존 BF16: 최대 GPU 메모리 14.44 GiB, 행동 예측 평균 0.283초.
- INT8: 최대 GPU 메모리 8.51 GiB, 행동 예측 평균 0.799초.
- 메모리는 약 41% 절약했지만, 이번 구현에서는 예측이 약 2.8배 느렸다.
- 예측 시간은 같은 검증 장면 32개에서 사진 전처리를 포함해 측정했다.
- 두 방식 모두 32개에서 정상적인 (1, 7) 행동 출력, NaN/무한대 없음.
- 메모리 값은 PyTorch의 peak allocated다. GPU 전체 사용량과는 다르다.
- 디스크에 있는 원본 모델 파일은 그대로다. 이번에는 불러올 때 양자화했다.

3. 실제 그릇 옮기기
같은 초기 상태 5개, 최대 행동 220번, 같은 사진 처리와 제어 변환을 사용했다.
기존 BF16 결과는 재사용했고, 시작 사진·초기 상태·시뮬레이터 버전 등을 대조했다.

초기 상태     기존 BF16           INT8
0             성공 / 86 step      성공 / 74 step
1             실패 / 220 step     성공 / 164 step
2             실패 / 220 step     실패 / 220 step
3             성공 / 83 step      성공 / 78 step
4             성공 / 70 step      실패 / 220 step

합계          3/5 (60%)           3/5 (60%)
평균 step     135.8               151.2
평균은 실패한 220 step 시도까지 포함한다.

성공 횟수는 같지만, 성공한 상태의 구성은 달라졌다.
5번만 확인했으므로 다른 환경에서도 같은 성능이라고 확정할 수는 없다.
실패는 제한된 220번 안에 LIBERO의 목표 조건을 달성하지 못했다는 뜻이다.
실패의 구체적인 물리적 원인은 아직 자세히 분석하지 않았다.
성공 판정도 안정적인 양쪽 집게 잡기까지 별도로 보장하는 것은 아니다.

볼 영상
- 02_BF16_vs_INT8_state_01.mp4: 기존은 실패, 8비트는 성공.
- 02_BF16_vs_INT8_state_04.mp4: 기존은 성공, 8비트는 실패.
왼쪽은 BF16, 오른쪽은 INT8이다.
영상은 행동 단계를 맞춰 20fps로 재생한다. 실제 예측 속도를 보여주는 영상은 아니다.

4. 오류와 해결
- 첫 오류: 8비트 모델에 .to()를 호출할 수 없다는 오류.
  Transformers가 양자화 표시를 끝내기 전에 Accelerate가 장치를 다시 옮기려 했다.
  이번 프로세스의 로딩 구간에만 force_hooks=True를 전달해 해결했다.
- 두 번째 오류: memory_efficient_backward 속성이 없다는 오류.
  기존 PEFT가 새 bitsandbytes에서 삭제된 예전 항목을 읽었다.
  계산에 사용되지 않는 호환 항목만 메모리에 보충했다.
- 해결 뒤 모델 로딩, 32개 행동 예측, 시뮬레이터 5개 시도가 모두 실행됐다.
- 기존 코드/체크포인트 300개 파일의 해시가 동일했다.
- openvla310, lerobot312, eval310의 pip freeze가 동일했다.
- bitsandbytes 0.45.5는 이번 실험의 deps 폴더에만 설치했다.
- 원래 학습 환경이나 패키지 파일은 수정하지 않았다.

5. 코드에서 어디를 읽을까?
experiment.py의 읽기용 사본을 이 폴더에 두었다. 실행은 원격 Linux에서 한다.
- 33줄 batch_benchmark(): 짧은 학습 처리량 측정.
- 68줄 make_inference(): 같은 모델을 BF16 또는 INT8로 불러오기.
- 125줄 infer(): 예측 검증·속도·메모리 측정과 시뮬레이터 평가.
- 182줄 audit(): 기존 파일과 환경 보존 확인.
실제 함수 위치는 code_locations.json에도 적혀 있다.

원격 원본 폴더:
/home/jovyan/projects/lerobot-openvla/outputs/batch_quantization/20261103T121901_577159Z

다시 실행할 때만 원격 터미널에서:
conda activate lerobot312
python /home/jovyan/projects/lerobot-openvla/outputs/batch_quantization/20261103T121901_577159Z/reproduce.py --batch-only

전체 비교를 다시 하려면 마지막의 --batch-only를 뺀다.
새 출력 폴더를 만들어 이전 결과를 보존한다.
재실행 도우미는 문법과 --help를 확인했다. 도우미로 전체 실험을 다시 반복하지는 않았다.
위에 보고한 실제 실험은 experiment.py의 각 단계를 실행한 결과다.

6. 이번에 가져갈 개념 두 개
- batch size: 한 번의 가중치 수정을 위해 묶는 장면 수.
  크게 묶으면 더 많은 메모리를 쓰며, 같은 epoch라도 수정 횟수가 달라진다.
- 양자화: 파라미터 개수는 유지하고 숫자 표현에 쓰는 비트를 줄이는 방법.
  메모리 절약, 예측 속도, 로봇 성공률은 각각 따로 측정해야 한다.

아직 하지 않은 일
- batch 8로 5 epoch 전체를 재학습한 뒤 성능 비교.
- 더 많은 새로운 초기 상태에서 양자화 전후 성공률 평가.
- 8비트 배포 파일 별도 저장, 속도 병목 분석, 4비트 실험.
- 이번 결과의 W&B 온라인 업로드. 현재 결과는 로컬 JSON/CSV/PNG/MP4에 남겼다.
