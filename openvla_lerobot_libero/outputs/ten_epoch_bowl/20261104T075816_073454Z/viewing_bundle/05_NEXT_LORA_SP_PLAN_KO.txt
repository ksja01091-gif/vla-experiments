다음 실험 준비: LoRA와 LoRA-SP 비교 (아직 실행하지 않음)

사용자가 지정한 논문:
Adaptive Capacity Allocation for Vision Language Action Fine-tuning
LoRA-SP = Select–Prune. 2024년의 동명 파라미터 일부 고정 방식과 다름.

비교에서 유지할 조건
- OpenVLA-7B, BF16 기본 모델, FP32 학습 파라미터
- 공개 LIBERO에서 선택·전처리한 동일한 학습 시범 40개 / 검증 시범 5개
- 동일한 사진·지시·행동 정규화, 동일한 q_proj/v_proj 수정 대상
- 같은 batch size, 학습 예산과 평가 상태를 맞춘 뒤 비교
- 논문은 π₀/SmolVLA와 실제 PiPER 로봇을 사용했다.
  우리 실험은 OpenVLA와 LIBERO에 적용한 비교이며 논문의 전체 실험 재현은 아니다.

추천할 대조군
1. 기존 LoRA rank8: 현재 기준. 학습 파라미터 4,194,304개.
2. LoRA rank128: 큰 수정 공간 자체의 효과를 구분할 대조군.
   같은 q/v 대상이면 학습 파라미터는 67,108,864개.
3. LoRA-SP: 논문의 초기 벡터 공간 128을 기준으로 연결한 뒤,
   실제 전체 학습 파라미터 수와 입력별 활성 rank를 함께 측정.

현재 rank8과 초기 공간128의 LoRA-SP만 비교하면
기법의 효과와 수정 공간 크기의 효과가 섞일 수 있다.
rank128 일반 LoRA를 함께 두는 이유가 이것이다.

먼저 할 일
- OpenVLA 연결과 checkpoint 저장·재로딩이 되는지 작은 시험으로 확인.
- 같은 장면 묶음으로 학습 시간·GPU 메모리를 짧게 실측.
- 단독 프로세스에서 행동 예측 시간·메모리를 실측.
- 그 결과와 필요한 학습 시간을 보고 본 학습 조건을 결정.

공식 코드 확인에서 발견한 점
- 초기 공간은 코드에서 r × num_experts로 결정돼, 설정 숫자를 그대로 rank로 읽으면 안 됨.
- rank 선택 경계에서 논문 설명과 공개 코드의 동작 차이가 있어,
  원문 기준을 명시하고 작은 수치 예제로 확인해야 함.
- 사용하지 않는 방향의 점수를 0으로 만들어도, 공개 코드의 행렬 계산은
  전체 공간을 사용하는 형태다. 활성 rank 감소만으로 속도·메모리 절약을 주장하지 않음.
- router가 추가되므로 작은 rank8 LoRA보다 메모리가 더 들 가능성도 있음.
- 본 학습 epoch, router 세부 설정, 논문 기준 구현과 공개 코드 차이를 기록한 후 실행.

기록할 것
- 학습: task loss, 보조 loss, 초당 장면 수, 최대 GPU 메모리
- 실행: 행동 예측 시간, 최대 GPU 메모리, adapter 파일 크기, 활성 rank
- 평가: 같은 초기 상태의 작업 성공 횟수·step 수·영상
- 가능하면 모델 선택에 쓰지 않은 새로운 초기 상태로 최종 확인

상태: 논문·코드 검토와 비교 설계 준비만 완료.
LoRA-SP 모델 학습·성능·메모리·속도 비교는 아직 실행하지 않았다.
